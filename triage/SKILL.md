# Triage — issue 清单消化（精简版）

把一批 issue/需求/外部 PR 推进一个小的分类状态机，产出可直接交给 `implement` 消费的 agent-ready brief。本地文件即 tracker（存 `~/.workbuddy/triage/`），不依赖 GitHub/Linear。

## 流程

1. **分类（category）**：
   - `bug` — 有东西坏了
   - `enhancement` — 新功能或改进
2. **验证（verify）**：
   - 能复现吗？（有复现步骤/日志？）
   - 已有测试覆盖吗？
   - 影响范围多大？
3. **盘问（grill，必要时）**：信息不足的条目，触发 `grilling` 补全需求
4. **产出 agent-ready brief**：存 `~/.workbuddy/triage/<date>-<id>.md`，模板见下

## Brief 模板

```markdown
# <issue 标题>

## 类型
bug / enhancement

## 描述
<问题或需求，从用户视角>

## 复现/验证
<复现步骤或验收方式>

## 建议方案
<实现方向，用领域词汇>

## 依赖
<前置 ticket/spec 引用>
```

## 规则

- 若在 issue tracker 上发评论，必须加免责声明：`> *This was generated by AI during triage.*`
- 只为信息足够的条目生成 brief；信息不足的先 grill

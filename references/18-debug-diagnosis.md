# ref-18 — Debug 诊断协议（确定性先行 → 假设-证据-实验 → 验证五态）

> **来源**：吸收 Agent Doctor 架构（ref-17）§10-13 的诊断/实验/验证引擎纪律，落地为 Debug 模式的可执行协议。
> **适用**：Debug 模式（bug/报错/异常行为）。Engineering/SDD 的排障环节可复用 §2-§4，不强制。

---

## 1. 协议总览

```
反馈环（复现） → [确定性先行] → 幸存假设 → [假设-实验环] → 根因确认 → 修复 → [验证五态]
```

核心纪律：**LLM 推理是最后一个输入，不是第一个**。确定性手段先跑，廉价地剪掉假设空间；LLM 只处理确定性手段无法解释的幸存假设。

## 2. 确定性先行阶段（先于任何 LLM 推理）

按序执行，命中即停（Early exit）：

| 顺序 | 手段 | 示例 |
|---|---|---|
| 1 | 复现 + 最小化 | 构造最小复现；缩小到单文件/单调用 |
| 2 | 日志/错误签名匹配 | 已知错误码、traceback 尾部、`grep` 已知签名 |
| 3 | 静态分析 | lint、类型检查、依赖树冲突（`pip check` / `npm ls`） |
| 4 | 差分 | 上次正常 vs 本次异常：git diff、配置 diff、环境 diff |
| 5 | 二分 | 注释/回退最近 N 个提交，定位引入点 |

若 1-5 已定位根因 → 直接修复，跳过 LLM。仅当全部未命中或签名新颖时，进入假设环并路由 LLM（§4 路由矩阵按任务定级）。

## 3. 假设-证据-实验环

每轮迭代产出结构化假设（这是与"随手试"式调试的核心区别）：

```text
H<n>: 假设陈述（一句话）
  支持证据:   [已观测到的支持事实]
  反对证据:   [已观测到的矛盾事实（可为空）]
  预期观察:   [若假设为真，下一步应看到什么]
  推荐实验:   [能判别此假设的廉价探针]
  来源:       rule | static | diff | llm
```

**实验选择启发式**（吸收 EIG 思想，去公式化）：优先选 **廉价 + 可逆 + 高判别力** 的探针——
读日志/查状态 = 廉价可逆，优先；改配置/重启共享服务 = 昂贵高风险，垫后且需回滚预案。

**收敛规则**：
- 实验观察与预期一致 → 提高置信度；不一致 → 推翻或修订假设。
- 多假设并存时，一次实验应优先选择能同时判别多个假设的探针。
- **Early exit**：置信度足以定位根因即停，不穷举所有可能。
- 同一路径失败两次 → 切换策略（换假设族/换证据源），不重试同路径（SDK §2.1 dead-end rule）。

## 4. 验证五态判定（§5.6 细则）

修复完成后按五态判定，**禁止默认 SUCCESS**：

| 状态 | 判定条件 | 后续动作 |
|---|---|---|
| **SUCCESS** | 前置条件复现 → 修复 → 后置条件全绿，无下游异常 | 收尾，沉淀案例 |
| **PARTIAL_SUCCESS** | 主症状消失，但存在次生异常/未覆盖路径 | 记录次生项，可再开一轮或明示降级交付 |
| **FAILED** | 症状依旧 | 回到假设环（证据已更新，重新剪枝） |
| **REGRESSION** | 目标修复但影响半径内出现新异常（依赖此处的其他功能被破坏） | 查 `DEPENDS_ON`/`CONFLICTS_WITH` 邻居，补回归修复 |
| **UNKNOWN** | 无法判定是否成功（信号不足/复现不稳定） | 补实验再判定；**禁止**硬归为 SUCCESS 或 FAILED |

**影响半径检查**（REGRESSION 的预防性前置）：修复验证时除目标功能外，检查其依赖方与共变模块（build/测试/调用方）各一条冒烟信号。

## 5. 问题案例库（Incident Memory 轻量版）

每次 Debug 会话收尾沉淀**轨迹**（不是摘要）——未来相似故障先查库再从头诊断：

```markdown
## [YYYY-MM-DD] 症状一句话（可搜索）
- 症状:    ...
- 环境:    项目/版本/关键依赖（快照）
- 确定性阶段命中: rule | static | diff | 无
- 轨迹:    假设链（H1→实验→观察→H2…）→ 根因 → 修复动作
- 验证:    五态结果 + 影响半径检查结论
- 教训:    一句话（下次可直接匹配的签名/坑位）
```

存放建议：项目内 `.workbuddy/debug-cases/` 或工作区记忆日志；检索方式 = `grep 签名`，命中则直接跳至对应修复动作验证，节省一次完整诊断。

# moe-eval — 评估闭环：黄金集、指标、回归、版本锁定

> **何时加载**: 改引擎/schema/纪律后、月度复评时、换模型前。
> **一句话**: 流水线的"好"是可测的——7 维评分 + 25 项回归 + token 效率，三者合起来才是真相。

---

## 1. 黄金集 — 商业化 7 维评分

每个批次交付前/后按 7 维打分，每维 0-5：

| 维度 | 考察点 | 合格线 |
|---|---|---|
| 可讨论性 | 有叙事缺口、有话题点 | ≥3 |
| 细节密度 | 8-Block 全维度丰富度、足部/服装细节 | ≥3 |
| 反差感 | 反 AI 疲劳、反套路（非大路货） | ≥3 |
| 组合性 | composition/expression 完整（QSv3 组合性指标） | ≥3 |
| 合规性 | validate 全绿、tags-only、无 forbidden | ≥3（一票否决：不合格不交付） |
| 多样性 | 跨场景动作/场景不重复（动作多样性审计） | ≥3 |
| 落地效率 | 从需求到交付的 token 成本与耗时 | ≥3 |

- **合格线**: 7 维全 ≥3；足袜控/反差系常见 3.4-3.7（可讨论性/细节密度高分）。
- **黄金集样本**: 20-50 个 CN 优先批次，覆盖 常规批次/反差系/足袜控/EQG-IP/essay 模式/多人 CP，每个带验收点（validate 全绿 + 各维达标 + 注入审计可查）。

## 2. 指标定义

| 指标 | 公式/定义 | 警报线 |
|---|---|---|
| 通过率 | validate 全绿批次 / 总批次 | <95% → 回查纪律执行 |
| 评分均值 | 7 维平均分（跨批次） | <3 → 设计层纪律没执行 |
| token 效率 | 总 token（含思考）/ 合格批次数 | 上升 → 查前缀/思考预算 |
| think-token 占比 | 思考 token / 总输出 | >70% 且评分没升 = overthinking → 砍预算 |
| 缓存命中率 | 命中请求 / 总请求 | <60% = 前缀构建坏了 → moe-cache.md §6 |
| 版本漂移 | 每月复跑黄金集 | 评分下降 → 引擎/模型升级回归 |

## 3. 回归工作流（25 项）

`test_flow_workflow.py` 25 项：可复现/随机/多人分配/注入/轮换补入/多样性审计/分块输出/质量锚/端到端。

```
任何改动（flow 代码 / schema / 纪律 / 提示词模板）
  → 跑 25 项回归（必过）
  → 小批量试跑（1 个批次）→ 7 维评分对比
  → 评分不降 → 放量；评分降 → 回滚改动
```

- 回归不过 = 改动不落地，无例外。
- **验证纪律**: 声称"完成"前必须跑验证（对应 coding SDK 的 verification-before-completion 纪律）。

## 4. 版本锁定

- 生产用**日期版批次号**: `design-spec-<theme>-20260816.json`，不用语义别名（`latest` / `new` 禁用）。
- 交付文件: `{前缀}_{主题}_{ts}.txt` + `.md`（ts = 时间戳，天然版本）。
- 引擎/模型/纪律版本变更记录在批次 notes 里——便于回溯评分漂移。

## 5. A/B 流程（换模型/换纪律前）

1. 冻结黄金集（固定样本 + 验收点）。
2. 旧配置跑一遍 → 基准评分。
3. 新配置跑一遍 → 对比评分 + token 成本。
4. 降幅 <2% 且省钱 → 可换；降幅 >5% → 回退。
5. 记录版本漂移，下月复跑。

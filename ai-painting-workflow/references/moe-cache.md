# moe-cache — 稳定前缀与缓存策略

> **何时加载**: 设计批量会话/排查 token 成本/优化缓存命中率时。
> **核心**: 字节一致前缀 = 缓存命中（DeepSeek 命中约 1/10 价格）。固定指令在前，易变内容最后。多一个空格/换行/时间戳就断缓存。

---

## 1. 为什么前缀要稳定

- MoE 厂商（DeepSeek 等）提供 prompt 缓存：**字节级相同的前缀**命中缓存，价格约 1/10。
- 缓存命中还附带质量收益：前缀被缓存 = 注意力有更多余量给 volatile 部分。
- 对批量流水线尤其重要：一次会话连出 6-30 个场景，前缀复用率越高越省。

## 2. 会话侧稳定前缀模板

```text
[系统提示（角色/纪律/思考协议/输出规范——MoE-5.1 那条）]   ← FIXED，永不变
[任务不变指令（8-Block 纪律/注入卡结构/核心纪律五条）]      ← FIXED
[弹药池（ammo/低热度清单，按需注入，版本化）]              ← 稳定，按批更新
-----------------------------------------------------------------
[本批用户输入（主题/角色/今日热度清单）]                   ← volatile，最后
[本批搜索结果]                                            ← volatile，最后
```

- 会话内换批次时：**只替换 volatile 段**，FIXED 段一个字不改。
- 别在 FIXED 段里写日期/批次号——那是 volatile，放后面。

## 3. 引擎侧 flow 组装顺序（勿乱调）

flow 的注入顺序本身就是一个稳定前缀：

```text
[角色锚 + 系列名（equestria girls）]   ← 固定前置（IP 锚点置首，v2.17）
[质量锚（masterpiece, best quality...）] ← 固定
[8-Block 固定模板结构]                 ← 固定
[场景 desc / essay / 注入卡 token]     ← volatile，后置
```

- **IP 锚点置首既是质量纪律也是缓存纪律**：固定前置 = 可缓存 + 避免冷门角色 OOC。
- 别为了"看起来整齐"重排 flow 输入——那会断缓存。

## 4. 缓存命中规则与检查

| 规则 | 说明 |
|---|---|
| 字节一致 | 前缀任何位置多一个空格/换行/时间戳 = 命中失败 |
| 稳定 80% + volatile 20% | 若 20% 内容常变：把稳定 80% 留在缓存前缀内，易变 20% 压到后面 |
| 长上下文 | 全文注入用于整书分析（按节引用）；代码库用关键文件+树；问答用 top-k 检索 |

## 5. runtime 复用即缓存（工程化命中）

- `runtime/verified_tags.json`（已 554 词）: 跨批次复用已验证标签——**别重复在线校验**。
- 预检脚本 0.1s/数百词 就是这个缓存的受益者：白名单/153K 命中/别名都记在里面。
- 纪律: 预检（快、缓存）→ flow（0.9s 权威终检）→ 在线验证**仅限** validate 报违规后的定向复核。

## 6. 排查清单（缓存命中率 <60% 时）

```text
□ FIXED 段是否真的固定？（日期/时间戳/批次号误入？）
□ 系统提示是否每次会话重新生成（换了措辞）？
□ 设计纪律文本是否被编辑/重排？
□ flow 输入顺序是否被动过？
□ volatile 段是否意外提前（用户输入插到了指令前）？
修复后复测命中率——这是 token 成本的第一杠杆。
```
